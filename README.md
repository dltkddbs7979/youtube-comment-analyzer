# 유튜브 댓글 분석기

댓글에 드러난 반응과 기대를 여섯 유형과 판단 보류로 나누고, 연구 질문에 답하는 한국어 웹 앱입니다. 기본 대상 영상은 [이성을 강하게 끌어당기는 연애운 주파수 STUDY WITH ME ver.](https://www.youtube.com/watch?v=15Gbo7Xcy80) (`15Gbo7Xcy80`)입니다.

이 앱은 댓글을 남긴 사람의 표현만 다룹니다. 전체 시청자의 생각으로 일반화하지 않으며, 주파수가 연애나 재회를 일으켰다는 결론을 만들지 않습니다.

## 설치와 실행

Python 3.10 이상을 권장합니다. 이 저장소를 만든 환경은 Windows, Python 3.14입니다.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

브라우저에서 `http://localhost:8501` 이 열립니다. 가상환경을 활성화하지 않아도 위 명령으로 실행할 수 있습니다.

형태소 분석에는 `kiwipiepy`를 씁니다. Java가 필요 없습니다. 설치에 실패하면 앱은 멈추지 않고 2글자 이상 어절로 키워드를 대체 계산하며, 화면에 그 사실을 알립니다.

## API 키

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만듭니다.
2. [YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com)를 사용 설정합니다.
3. 사용자 인증 정보에서 API 키를 만듭니다.
4. `.env.example`을 `.env`로 복사하고 다음처럼 넣습니다.

```text
YOUTUBE_API_KEY=여기에_키
```

`.env`는 `.gitignore`에 들어 있습니다. 키를 깃에 올리지 마세요.

화면의 비밀번호 입력란에 키를 넣어도 됩니다. 그 값은 세션 메모리에서만 쓰며 파일, 로그, 다운로드에 저장하지 않습니다. 입력란에 값이 있으면 환경 변수보다 우선합니다. **세션의 API 키 지우기**로 지울 수 있습니다.

키가 없거나 형식·권한·할당량 오류가 있으면 한국어로 원인과 해결 방법을 보여 줍니다. 키 값과 API 원문 오류는 화면에 올리지 않습니다. 키가 없을 때는 **모의 데이터로 화면 확인**을 선택할 수 있습니다.

## 모의 데이터

`data/sample_comments.json`은 기능 확인용으로 만든 글입니다. **실제 유튜브 댓글이 아닙니다.** 화면 위쪽에 모의 데이터 안내가 나오고, 결론 문장에도 같은 사실이 들어갑니다. 실제 수집 결과와 섞어 해석하지 마세요.

## 화면 흐름

1. 분석 설정: 영상 주소, 키 상태, 수집 상한, 분류 방식, 실행
2. 수집 상태: 페이지 수, 댓글 수, 수집 시각, 오류와 부분 수집 안내
3. 분석 요약: 수집 수, 분류 대상, 판단 보류, 중복·제외와 사유
4. 핵심 결과: 가로 막대그래프, 같은 수치의 표, 키워드, 연구 질문 답
5. 세부 결과: 유형별 사례, 근거와 참고 점수, 유형 비교, 답글, 작성 시각
6. 댓글 검토: 검색·필터, 주 분류 수정, 낮은 참고 점수 확인
7. 자료 내보내기: CSV, JSON, 제외·중복 CSV, 차트 PNG
8. 해석상 한계와 이번 분석의 결론

차트를 그릴 수 없어도 같은 수치는 표로 볼 수 있습니다.

## 수집 범위와 API 한계

공식 [YouTube Data API v3](https://developers.google.com/youtube/v3)만 사용합니다. 비공식 스크래핑은 하지 않습니다.

- `commentThreads.list`로 댓글 스레드를 페이지당 최대 100개, `order=time`으로 가져옵니다.
- 응답에 일부만 들어 있는 대댓글은 `comments.list`의 `parentId`로 이어서 가져옵니다.
- 호출 1회는 할당량 1단위입니다. 기본 일일 할당량은 프로젝트마다 Google이 정합니다(보통 10,000단위).
- 최대 수집 수의 기본값은 5,000건, 상한은 20,000건입니다. 0을 넣으면 5,000건까지입니다.
- 페이지 상한은 80, 스레드당 대댓글 추가 페이지는 10, 일시 오류 재시도는 3회, 대기 시간은 0.8초·1.6초·3.2초입니다.
- 상한에 닿거나 할당량이 끝나면 그때까지 받은 댓글만 분석하고, 부분 수집이라고 표시합니다.
- 댓글 비활성화, 공개 댓글 없음, 권한 부족, 할당량 초과, 네트워크 오류를 구분해 안내합니다.
- 삭제·비공개·검토 대기 댓글과 API가 주지 않은 대댓글은 포함되지 않습니다. API의 `commentCount`와 수집 수가 다르면 그 차이를 화면에 알립니다.
- 작성자 이름, 채널, 프로필은 수집하지 않습니다.

## 전처리

- HTML 엔티티를 풀고, 태그·공백·줄바꿈을 정리합니다. 원문(`댓글원문`)과 분석용 텍스트(`정제텍스트`)를 따로 둡니다.
- 분석용 텍스트의 URL은 `[URL]`로 바꿉니다. 원문에는 URL을 남깁니다.
- 이모지, 반복 문자, 웃음 표현은 지우지 않습니다. 호환 자모 `ㅋ`, `ㅎ`는 정규화 뒤에도 웃음으로 알아보게 되돌립니다.
- 전화번호, 이메일, 주민등록번호 형태의 숫자는 `[전화번호]`, `[이메일]`, `[식별번호]`로 가립니다.
- 공백을 맞춘 뒤 완전히 같은 댓글은 먼저 작성된 하나만 남기고 중복 수를 보고합니다.
- 제외: 텔레그램·오픈채팅·구독 유도 등 홍보, 글자·이모지가 없는 기호, 같은 문자가 30자 이상 반복되는 무의미 문자열, 빈 문자열. 제외·중복 댓글은 화면과 CSV에서 다시 볼 수 있습니다.
- 짧은 감탄, 이모지, 웃음은 제외하지 않습니다. 가장 가까운 여섯 유형으로 분류하고 참고 점수는 낮게 둡니다.

## 분류 기준

주 분류는 하나이고, 다른 유형의 점수가 충분하면 보조 태그를 붙입니다. 1위와 2위가 가까워도 점수가 더 높은 유형을 주 분류로 두고 2위는 보조 태그로 남깁니다. 규칙 점수가 1.15 미만이면 문장 단서로 가장 가까운 유형을 고르고 참고 점수를 0.44 이하로 제한합니다. 판단 보류는 문자·이모지·웃음 신호가 전혀 없을 때만 쓰며, 쓸 경우 비율의 분모에 포함됩니다.

| 유형 | 기준 |
| --- | --- |
| 효과 경험형 | 들은 뒤 연락, 재회, 고백, 연애 시작처럼 원하던 일이 일어났다고 본인이 서술할 때. 작성자의 인식이나 주장이지 실제 효과의 증거가 아닙니다. |
| 기대·희망형 | 아직 일어나지 않은 일을 바라거나 기원·다짐할 때. “연락 왔으면 좋겠다”는 여기 해당합니다. |
| 사용 방법 질문형 | 횟수, 시간, 이어폰·스피커, 볼륨, 듣는 시점을 물을 때. 소망이 섞여 있으면 질문이 중심일 때 주 분류로 둡니다. |
| 공감·추천형 | 공감, 추천, 감사, 응원이 중심일 때. 본인 결과 서술이 더 분명하면 효과 경험형을 우선합니다. |
| 회의·비판형 | 효과가 없다고 말하거나 근거, 광고성, 미신, 사기를 문제 삼을 때. |
| 유머·조롱형 | 농담, 밈, 비꼼이 중심일 때. 웃음만 있는 글도 여기 두되 참고 점수는 낮습니다. 조롱이 중심이면 농담으로 적은 결과를 경험으로 받지 않습니다. |
| 판단 보류 | 한글·영문·숫자·이모지·웃음이 없어 여섯 유형 중 고를 수 없을 때만. |

소망 표현이 있으면 경험 점수를 낮춥니다. “안 왔어요”처럼 부정이 붙은 연락은 경험으로 세지 않습니다. 코드의 규칙과 가중치는 `src/classifier.py`에 있습니다.

### 참고 점수

신뢰도라는 이름의 값은 **검증된 확률이 아닙니다.**

- 기본 0.42
- 1위와 2위 점수 차 × 0.08 (최대 0.28)
- 가중치 1.6 이상인 규칙 하나당 0.05 (최대 0.15)
- 의미 있는 길이가 12 이상이면 0.06, 20 이상이면 0.12
- 결과는 0.20 이상 0.92 이하
- 의미 있는 길이가 8 미만이면 0.60, 2 미만이면 0.45를 넘기지 않음
- 강한 규칙 없이 가장 가까운 유형으로만 분류한 경우는 0.44를 넘기지 않음
- 판단 보류는 분류 신호가 없을 때만 쓰며 0.22
- 0.50 미만은 검토 권장

분류 정확도를 보장하지 않습니다. 사용자가 주 분류를 고치면 차트와 다운로드가 함께 바뀌고, 점수는 수정 전 자동 분류의 참고 값으로 남습니다.

외부 LLM이나 로컬 ML 모델은 선택 사항입니다. LLM은 동의 확인란을 켜야 댓글 원문을 외부로 보내며, 기본 실행은 규칙 기반입니다. 학습된 모델 파일이 없으면 ML 경로는 동작하지 않습니다.

## 키워드

`kiwipiepy`로 명사, 고유명사, 동사, 형용사, 어근, 외국어를 뽑습니다. 한 댓글 안에서는 같은 단어를 한 번만 셉니다.

`data/stopwords.txt`의 일반어는 제외합니다. 한 줄에 하나이며 `#`으로 시작하는 줄은 설명입니다. 영상 제목에 있는 단어는 지우지 않고 반영 점수를 빈도의 0.35배로 낮춥니다. 그래서 “주파수” 같은 제목어가 결과 전체를 차지하지 않게 하면서, 실제로 많이 쓰이면 남을 수는 있습니다.

## 대표 댓글

좋아요 수만으로 고르지 않습니다. 해당 유형의 참고 점수, 특징이 드러나는 분량, 이미 고른 글과의 내용 차이를 보고 유형마다 최대 3건을 고릅니다. 좋아요는 보조 참고입니다. 이 글은 작성자의 사례일 뿐 시청자 전체나 주파수 효과를 대표하지 않습니다.

비율의 분모는 중복 제거와 홍보·무의미 댓글 제외 뒤의 분류 대상 수입니다. 판단 보류를 포함합니다.

## 한글 글꼴과 차트

차트 PNG와 확인용 이미지는 Matplotlib으로 그리고, 글자를 경로로 바꿉니다. 브라우저 기본 글꼴에만 기대지 않습니다. 화면의 막대그래프는 같은 수치를 HTML로 그려 글자 크기가 줄어들지 않게 했고, 좁은 화면에서는 유형 이름을 막대 위로 올립니다. 글꼴 파일이 없어도 HTML 차트와 표는 남고, PNG는 글꼴이 있을 때만 만듭니다. 글꼴이 전혀 없으면 깨진 이미지를 그리지 않고 안내합니다.

- 글꼴: IBM Plex Sans KR Regular
- 저작권: Copyright 2017 IBM Corp. Reserved Font Name "Plex"
- 라이선스: SIL Open Font License 1.1 (`assets/fonts/OFL.txt`)
- 출처: [google/fonts의 ibmplexsanskr](https://github.com/google/fonts/tree/main/ofl/ibmplexsanskr)
- 파일: `assets/fonts/IBMPlexSansKR-Regular.ttf`
- 글꼴 파일을 수정하거나 이름을 바꾸지 않았습니다.

가로 막대에는 댓글 수와 비율, 분모 설명, 기호·색·무늬가 함께 있는 범례가 있습니다. 좁은 화면에서는 유형 이름이 막대 위에 놓여 숫자와 겹치지 않습니다.

화면 본문은 `Malgun Gothic`, `Apple SD Gothic Neo`, `Noto Sans KR`, IBM Plex Sans KR 순으로 지정합니다. 알려진 한글 UI 글꼴이 없는 환경에서는 번들 글꼴을 페이지에 넣습니다.

### 한글이 보이는지 확인하는 방법

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_analysis -v
.\.venv\Scripts\python.exe scripts\render_korean_check.py
```

`output/korean_chart_check.png`를 열어 다음을 봅니다.

- 제목, 축, 유형 이름, 범례가 한글로 보이는지
- 네모(□)나 겹침, 잘림이 없는지
- 막대 끝의 `N건 (N.N%)`가 그래프 안에 들어가는지

앱에서는 **모의 데이터로 화면 확인** 뒤 **분석 실행**을 누르고, 차트와 그 아래 표, 댓글 카드의 줄바꿈을 함께 확인합니다. 브라우저 너비를 줄였을 때 표와 카드가 화면 밖으로 잘리지 않는지도 봅니다.

## 내보내기

파일 이름에는 영상 ID와 수집 시각이 들어갑니다.

- CSV: UTF-8 BOM. 댓글 원문, 정제 텍스트, 주 분류, 보조 태그, 참고 점수, 근거, 좋아요 수, 작성 시각, 대댓글 여부 등. Excel에서 한글이 깨지지 않게 하기 위한 형식입니다.
- JSON: UTF-8, `ensure_ascii=False`. 영상·수집 정보, 전처리 요약, 통계, 키워드, 연구 질문 답, 결론, 분류 결과.
- 화면에서 고친 주 분류가 두 파일에 반영됩니다.
- 작성자 식별 정보와 API 키는 넣지 않습니다.

## 오류

| 상황 | 안내 |
| --- | --- |
| 키 없음, 형식 오류, 권한 오류 | 키를 어디에 넣는지와 사용 설정 확인 |
| 잘못된 주소·영상 ID | 올바른 주소 예시 |
| 댓글 비활성화, 댓글 없음 | 다른 영상 또는 공개 댓글 여부 |
| 할당량, 네트워크, 일시 장애 | 재시도와 대기, 할당량 초기화. 우회 수집은 없음 |

| 분석할 텍스트 없음 | 제외 사유와 빈 결과 안내 |
| 저장 실패 | 브라우저 다운로드 권한 확인 |
| 글꼴 없음 | 차트 대신 표와 글꼴 파일 안내 |

## 해석할 때

댓글 작성자는 시청자 전체가 아닙니다. “효과를 경험했다고 서술했다”와 “효과가 있었다”는 다른 말입니다. 청취 뒤에 일이 있었다고 적어도 인과로 보지 않습니다. 표본이 적거나 판단 보류가 많으면 결론은 그 한계를 먼저 말합니다.
